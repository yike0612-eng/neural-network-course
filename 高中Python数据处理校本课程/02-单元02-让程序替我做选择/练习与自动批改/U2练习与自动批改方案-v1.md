# U2 练习与本地自动批改方案 v1.0

## 一、设计目的

U2 的自动批改围绕“规则是否透明、边界是否正确、函数是否可复用”展开。学生先把自然语言建议转为函数，再通过多组输入检验规则顺序，而不是只让程序在一个示例下输出“看起来正确”的结果。自动批改用于检查基础函数行为并提供即时反馈；它不评价决策流程图、规则优先级理由、数据责任反思或口头解释。

练习按照“必做—选做—挑战”设计。必做任务覆盖布尔表达式、单一规则、多分支函数和批量处理；选做任务统计建议类别；挑战任务处理无效天气输入或比较规则优先级。基础自动批改只验证必做题及一个可选加分题。

## 二、提交接口与练习任务

学生提交一个 `u2_submission.py` 文件。文件只包含函数定义；不得包含 `input()`、`print()`、文件读写、网络访问、导入模块或顶层测试代码。展示版程序 `campus_task_helper.py` 可单独保存，供同伴试运行和课堂展示。

| 练习 | 学习目标 | 必须实现的函数 | 核心测试 | 反馈重点 |
|---|---|---|---|---|
| E1 布尔规则 | 将简单规则写成返回布尔值的函数。 | `is_short_time(free_minutes)` | 9、10、11。 | 阈值边界与返回值类型。 |
| E2 基础建议 | 用条件判断区分任务未完成、时间短与一般情况。 | `basic_advice(free_minutes, task_done)` | 未完成、5 分钟、10 分钟。 | 规则优先级与 `if/elif/else`。 |
| E3 多分支助手 | 将天气、时间、任务状态整合为可解释建议。 | `suggest_activity(weather, free_minutes, task_done)` | 雨天、晴天 30 分钟、组合边界。 | 是否覆盖三类输入与边界。 |
| E4 批量处理 | 用循环处理多条模拟情境。 | `batch_advice(situations)` | 3 条字典记录。 | 是否保留记录顺序与逐条调用规则。 |
| E5 选做统计 | 对建议文本做简单统计。 | `count_indoor_advice(advice_list)` | 含“室内”的建议列表。 | 循环与计数。 |

## 三、规定返回格式

自动批改采用函数返回值而非匹配 `print()` 输出，使行为测试稳定、反馈具体。学生可在展示文件中使用 `print()` 让程序更易读；但自动批改提交文件须遵守下表。

| 函数 | 返回格式 |
|---|---|
| `is_short_time(9)` | `True`；10 或更大时返回 `False`。 |
| `basic_advice(5, True)` | `"短时整理"`；任务未完成时返回 `"完成任务"`；其他情况返回 `"自由安排"`。 |
| `suggest_activity("雨", 20, True)` | `"室内活动"`；规则细节见模板注释。 |
| `batch_advice(situations)` | 与输入等长的字符串列表，例如 `["短时整理", "室内活动", "完成任务"]`。 |
| `count_indoor_advice([...])` | 整数，表示列表中等于 `"室内活动"` 的元素数。 |

## 四、建议规则优先级

自动批改使用的基础规则如下。学生在展示版中可自行丰富建议文本，但提交版应按此规则返回规定的短文本，以便反馈一致。

```text
1. task_done 为 False        → “完成任务”
2. free_minutes < 10         → “短时整理”
3. weather == “雨”           → “室内活动”
4. weather == “晴” 且 free_minutes >= 30 → “户外活动”
5. 其他情形                  → “自由安排”
```

规则顺序本身也是学习对象。对“雨天且只有 5 分钟”的模拟输入，本练习按“时间短优先”返回“短时整理”；学生可在反思中讨论是否愿意改用“天气优先”，但应以测试用例说明差异。

## 五、批改机制与安全边界

`grade_u2.py` 复用 U1 的课堂批改原则：首先检查文件结构和受限语法；然后在独立、超时受限的子进程中调用函数；最后输出逐项通过/未通过及可操作提示。批改器拒绝导入、顶层执行、文件/网络操作、属性调用和未允许的函数调用，降低初学者误操作风险。

> **重要：** 这不是安全沙箱。教师只能在隔离、受控的课堂设备或账号上对可信学生文件使用；不得批改来自互联网、身份不明来源或包含恶意意图的代码。学校若需处理不受信任代码，应使用容器、虚拟机或统一在线判题平台。

## 六、运行方式

将 `grade_u2.py` 与学生文件放在同一文件夹，或以路径指定文件：

```bash
python grade_u2.py u2_submission.py
```

推荐在第 7、8、9 课时末各运行一次。学生应每次只根据第一条未通过反馈做最小修改，再重新运行；第 10 课时的最终评价仍须结合规则流程图、同伴测试和边界反思。

## 七、评价分工

| 学习证据 | 推荐评价方式 | 自动批改覆盖 |
|---|---|---|
| E1—E4 函数行为 | 自动批改 + 调试日志。 | 覆盖。 |
| 建议文字的可读性 | 同伴试运行、教师观察。 | 不覆盖。 |
| 规则流程图与优先级理由 | 量规审阅、展示追问。 | 不覆盖。 |
| 规则公平性、遗漏与人工判断 | 反思文本、课堂讨论。 | 不覆盖。 |
| 挑战任务 | 教师审阅、学生解释。 | 仅 E5 可选覆盖。 |
