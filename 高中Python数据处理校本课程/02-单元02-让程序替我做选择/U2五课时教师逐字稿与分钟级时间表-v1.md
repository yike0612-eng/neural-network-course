# U2《让程序替我做选择》五课时教师逐字稿与分钟级时间表 v1.0

**适用情境：** 高一、高二；已完成 U1 或至少能读懂基础 `if/else` 与 `for` 循环；5 × 45 分钟；普通离线 Windows 机房。  
**单元产出：** 一个校园任务助手、一个规则决策流程图、一份规则边界与人工判断反思。  
**核心立场：** 程序依据人写下的规则给出建议，不能在信息不足、规则不透明或涉及个人权益时替代人的判断。

> **固定课堂句式：** “先写清规则，再写代码；先预测输出，再运行；先测边界，再发布。”

## 一、五课时总览

| 课次 | 核心问题 | 本课最小达成 | 当堂留下的证据 |
|---:|---|---|---|
| 1 | 一条日常建议怎样变成可判断的规则？ | 能写出输入、条件、结果和一项人工判断因素。 | 规则表与退出卡。 |
| 2 | 多条规则同时成立时，程序先听谁的？ | 能解释多分支的优先级，并测试 9/10/11 分钟边界。 | 优先级排序卡与边界记录。 |
| 3 | 怎样一次处理多组情境？ | 能让循环逐条调用规则函数。 | 情境列表与输出核对。 |
| 4 | 怎样证明规则不只在一个例子里有效？ | 能写出普通、边界、组合三类测试。 | 测试表与修改记录。 |
| 5 | 怎样让别人看懂并质询我的规则？ | 能提交程序、流程图、边界反思并完成同伴试运行。 | 三类成果与同伴反馈。 |

## 二、课前统一准备

教师准备 `校园任务助手_起始代码.py`、学生学习单、U2 练习与自动批改资源、规则卡和流程图模板。课堂只使用教学模拟输入：天气、可支配时间、任务是否完成。不得录入学生真实成绩、行为、健康、精确位置或个人日程；程序输出只是一条可讨论的建议，不得用于纪律评价、成绩判定或资源分配。

教师应在第 1 课前打开起始代码与参考实现，确认编辑器能运行 `.py` 文件。若出现设备问题，学生可先在纸面规则表和测试表中完成任务，再与同伴共用可用设备验证；不在课堂中临时安装扩展库。

# 第 1 课：规则从哪里来？

**本课目标：** 识别模糊规则；把建议拆成输入、条件、结果和优先级；能用比较与布尔表达式写出可判断条件；说明一项仍需人工判断的因素。  
**教师材料：** U2 学习单、规则卡、`weather`、`free_minutes`、`task_done` 示例。  
**板书固定区：** `输入 → 条件 → 结果 → 优先级`；`规则清楚，程序才可解释`。

| 时间 | 教学环节 | 教师逐字稿与操作 | 学生动作与教师观察 |
|---|---|---|---|
| 0:00—4:00 | 从 U1 连接 U2 | **教师说：**“U1 里，程序根据数据计算总量和达标天数。今天我们进一步问：如果程序要给出一条建议，规则是谁写的？规则清不清楚？有没有遗漏？代码不会自己产生公平规则，它只会执行我们写下的条件。” | 学生回忆 U1 的条件判断。教师不复讲全部语法，只确认 `>=` 和 `if/else` 基础。 |
| 4:00—10:00 | 识别模糊建议 | 投影：“天气不好就不要外出”“时间够就去运动”。**教师说：**“请圈出这两句话里程序无法直接判断的词。什么叫天气不好？多久算够？如果任务还没完成呢？”给 90 秒小组讨论。 | 预期答案：天气阈值不清、时间标准不清、任务状态未知。教师追问：“怎样让其中一个词变成变量或条件？” |
| 10:00—20:00 | 建立规则四要素 | **教师说：**“一条能写进程序的规则，至少要有四部分：输入是什么；条件是什么；结果是什么；如果多个条件同时成立，谁在前面。”示范：输入 `task_done`；条件 `not task_done`；结果“先完成当前任务”；优先级“放在前面”。 | 学生完成学习单中的规则表前两行。教师巡视时要求条件避免“差不多”“适合”等模糊词。 |
| 20:00—30:00 | 布尔表达式练习 | 依次展示 `free_minutes >= 10`、`weather == "雨"`、`not task_done`、`weather == "雨" and free_minutes >= 10`。**教师说：**“代码里的 `==` 是比较，不是赋值。每一条表达式都必须能回答真或假。”教师给出三组输入，要求学生预测真/假。 | 学生填写真/假并说明理由。若混淆 `=` 和 `==`，追问：“这一行是保存值，还是提一个可判断的问题？” |
| 30:00—38:00 | 规则卡挑战 | **教师说：**“每组抽三张卡：天气、时间、任务状态。写出一句完整规则：如果……，那么……。再写出一个你认为应排在前面的规则，并解释原因。” | 小组拼规则。教师检查是否包含输入、条件和结果。 |
| 38:00—42:00 | 人工判断边界 | **教师说：**“即使规则写得清楚，程序还看不见什么？例如，学生是否愿意、场地是否安全、是否需要教师帮助。请写下一项不能交给程序决定的因素。” | 独立写作。教师强调建议不是命令。 |
| 42:00—45:00 | 退出卡与收束 | **教师说：**“退出卡写两句：一条今天能写进程序的规则；一项程序不应替人判断的因素。下节课，我们让多条规则排队，讨论谁先执行。” | 提交退出卡，保存规则表。 |

**即时调整规则：** 若多数学生仍用“天气不好”“时间够”等模糊条件，下一课开场先用 5 分钟改写两条规则，不急于多分支。若 `=` 与 `==` 混淆普遍，先做双栏对比再进入函数代码。

# 第 2 课：多分支与优先级

**本课目标：** 读懂 `if/elif/else`；理解每个后续分支只在前面条件不成立时才被检查；能用边界输入说明规则顺序；写出优先级理由。  
**教师材料：** 规则条、函数骨架、9/10/11 分钟边界卡。  
**板书固定区：** `if → elif → else`；`先执行的规则 = 更高优先级`。

| 时间 | 教学环节 | 教师逐字稿与操作 | 学生动作与教师观察 |
|---|---|---|---|
| 0:00—4:00 | 规则回顾 | **教师说：**“昨天我们把模糊建议写成了可判断条件。今天的问题是：雨天、时间很短、任务未完成可能同时出现，程序先处理哪一个？” | 学生口头回答。教师板书三个条件。 |
| 4:00—12:00 | 规则排序 | 发放混乱规则条。**教师说：**“请把规则排成你认为合理的顺序。没有唯一顺序，但必须写出理由。想一想：如果任务还没完成，是否先讨论天气？” | 小组排序。教师要求每组能说出第一条规则的优先理由。 |
| 12:00—22:00 | 映射为代码 | 展示 `suggest_activity()` 骨架。**教师说：**“`if` 先检查第一条；只有它不成立，`elif` 才有机会被检查；`else` 是前面都不成立时的默认情况。你希望一组输入输出一条建议，还是多条相互冲突的建议？” | 学生标注每个分支对应的规则。教师对比多个独立 `if` 与 `if/elif/else`，让学生观察输出差异。 |
| 22:00—32:00 | 预测—运行 | 提供四组输入：任务未完成；晴天 5 分钟；雨天 20 分钟；晴天 30 分钟。**教师说：**“先写预测和依据，后运行。若不一致，不要说‘代码错了’，先问：哪条规则先成立？” | 学生预测、运行并记录。教师收集一个“两个条件同时成立”的例子。 |
| 32:00—40:00 | 边界实验 | **教师说：**“现在只改 `free_minutes`：9、10、11。10 分钟到底归哪一边，取决于你写的是 `< 10` 还是 `<= 10`。规则边界不是小细节，它决定真实输出。” | 学生运行 3 组边界输入，在学习单记录预期/实际。 |
| 40:00—43:00 | 优先级说明 | **教师说：**“请完成一句：‘我把______放在前面，因为______。’理由必须与任务目标或安全边界有关，不是‘我喜欢’。” | 独立完成，2 人分享。 |
| 43:00—45:00 | 收束 | **教师说：**“今天我们让一组输入只得到一条清楚建议。下节课，我们让同一规则处理多组模拟情境。” | 保存函数文件。 |

**即时调整规则：** 若多数学生认为 `elif` 无论如何都会执行，使用一组输入逐行追踪，并让学生遮住后续分支观察执行路径。若边界错误超过半数，U2 第 4 课前安排 5 分钟边界复习。

# 第 3 课：循环处理多组情境

**本课目标：** 理解“一条字典记录”和“多条记录列表”；用 `for` 循环逐条调用规则函数；比较输出条数与输入记录数；完成一个简易建议类别统计。  
**教师材料：** 情境列表、起始代码、手动判断卡。  
**板书固定区：** `一条记录 → 一次函数调用 → 一条建议`；`多条记录 → for 循环`。

| 时间 | 教学环节 | 教师逐字稿与操作 | 学生动作与教师观察 |
|---|---|---|---|
| 0:00—5:00 | 手动模拟 | **教师说：**“先不写循环。这里有两条模拟情境：晴天 5 分钟且任务完成；雨天 20 分钟且任务完成。请用昨天的规则手动给出建议。” | 学生按规则表判断。教师确认输出与规则顺序一致。 |
| 5:00—11:00 | 读一条记录 | 展示 `{"weather": "雨", "free_minutes": 20, "task_done": True}`。**教师说：**“这是一条记录。键像字段名，值是这一条情境中的信息。请指出天气、时间、任务状态分别在哪里。” | 学生标出键和值。教师避免引入与任务无关的字典操作。 |
| 11:00—20:00 | 从一条到多条 | 展示 `situations = [...]`。**教师说：**“列表把多条记录排在一起。循环每一轮拿出一条 `situation`，再把其中三个输入交给同一个函数。函数不需要知道这是第几条记录，它只按规则返回建议。” | 学生预测两个情境会产生几条输出。 |
| 20:00—33:00 | 完成循环调用 | **教师说：**“现在完成最小骨架：遍历 `situations`，从当前记录取出三个值，调用 `suggest_activity()`，再打印建议。每加两行就运行一次。”教师巡视提问：“这一轮的 `situation` 是哪一条？输出为什么应该与记录数相等？” | 学生完成代码并运行。基础学生使用完整骨架；进阶学生添加记录编号。 |
| 33:00—41:00 | 简易统计 | **教师说：**“我们不需要复杂分析。只做一个计数：输出中有几次‘室内’建议。先预测改一条晴天记录为雨天后，计数会怎样变。” | 学生设置计数变量、运行、解释变化。 |
| 41:00—44:00 | 退出卡 | **教师说：**“写一句：循环在重复什么？函数在重复什么？两者不是同一件事。” | 独立写作。教师据此判断是否需要下节课先复习函数调用。 |
| 44:00—45:00 | 收束 | **教师说：**“现在规则可以处理多组输入。下节课，我们要证明它不只在一组例子里看起来正确。” | 保存程序。 |

**即时调整规则：** 若学生把字典字段名与值混淆，先让其在纸面上用颜色配对；不要继续加统计。若输出数与记录数不一致，先定位循环缩进和 `print` 所在位置。

# 第 4 课：函数与测试用例

**本课目标：** 能说明函数名、参数与返回值；区分 `print` 与 `return`；设计普通、边界和组合测试；依据测试修改一处规则或确认其合理性。  
**教师材料：** 测试表、函数代码、边界与组合卡。  
**板书固定区：** `输入 → 函数规则 → 返回建议`；`例子不等于测试`。

| 时间 | 教学环节 | 教师逐字稿与操作 | 学生动作与教师观察 |
|---|---|---|---|
| 0:00—4:00 | 回顾函数调用 | **教师说：**“昨天循环多次调用同一个函数。今天我们问：怎样证明这个函数不只是碰巧在两条记录上看起来正确？” | 学生说出函数接受的三个输入。 |
| 4:00—12:00 | 拆解函数 | 指向函数名、参数与 `return`。**教师说：**“函数像一份透明的规则说明书。参数是输入；函数内部处理规则；`return` 把建议交回外部代码。`print` 是显示，`return` 是交回结果，它们用途不同。” | 学生填写输入—处理—输出表。教师检查是否能说出外部 `print(suggest_activity(...))` 的关系。 |
| 12:00—22:00 | 设计三类测试 | **教师说：**“测试至少有三类：普通情形，看看常见输入；边界情形，看看 9、10、11；组合情形，看看两个条件同时成立。测试不是为了抓错，而是检查规则是否符合自己的设计意图。”示范一行测试表。 | 学生设计至少 6 组测试。教师检查有 9/10/11 和至少一条任务未完成+雨天等组合输入。 |
| 22:00—34:00 | 运行与记录 | **教师说：**“逐组运行。每次写预期、实际和依据。如果不一致，不要先改输出文字，而要问：是规则写错，还是优先级和我原本的意图不同？” | 学生运行、记录。有不一致者按调试四步做最小修改；完全符合预期者说明理由。 |
| 34:00—40:00 | 同伴审查 | **教师说：**“交换测试表。你不需要替同伴判断规则是否唯一正确，只要找一个他没有覆盖的边界或组合情境。” | 同伴留下具体建议。教师提醒反馈用“如果……会怎样？”而非“你写错了”。 |
| 40:00—43:00 | 价值测试分享 | **教师说：**“请任选一组你认为最有价值的测试，说明它为什么比一个普通晴天 30 分钟例子更能检验规则。” | 2—3 名学生分享。 |
| 43:00—45:00 | 收束 | **教师说：**“下节课我们发布作品。别人不只看你的输出，还会问：规则是什么、边界在哪里、什么时候应该让人决定。” | 保存测试记录。 |

**即时调整规则：** 若学生只设计普通样例，教师发放“边界—组合”强制卡，而不是增加更多语法。若 `print` 与 `return` 混淆，先让学生手写“谁需要使用这个结果”再回到代码。

# 第 5 课：发布校园任务助手

**本课目标：** 完成并自测程序；绘制规则流程图；完成同伴试运行；在 90 秒展示中说明一组输入输出、一组边界测试和一项人工判断边界；提交反思。  
**教师材料：** U2 量规、流程图模板、同伴试运行表、测试表。  
**板书固定区：** `输入 → 条件与优先级 → 输出建议`；`建议 ≠ 命令`。

| 时间 | 教学环节 | 教师逐字稿与操作 | 学生动作与教师观察 |
|---|---|---|---|
| 0:00—3:00 | 明确三类成果 | **教师说：**“今天交付三项：可运行规则程序、能讲清顺序的流程图、能说明边界的反思。程序给出建议不代表它替人做决定；你必须说明什么时候应保留人工判断。” | 学生打开提交清单。 |
| 3:00—13:00 | 自测与完善 | **教师说：**“用不少于 6 组测试自测，检查三件事：普通情境、9/10/11 边界、两个条件同时成立。先确认程序再优化文字。” | 学生完成自测。教师优先支持不能稳定运行者，允许使用基础函数骨架。 |
| 13:00—21:00 | 决策流程图 | 教师示范：输入框、条件菱形、优先分支、输出框、不适用情形。**教师说：**“图的顺序必须与代码一致。让没有看过代码的人沿箭头走，也能说出为何得到这条建议。” | 学生绘图。教师检查是否有输入、条件、输出和人工判断边界。 |
| 21:00—29:00 | 同伴试运行 | **教师说：**“交换程序和测试表。试运行者要完成三件事：输入一组测试；检查输出是否符合流程图；提出一个‘什么情况下不该让程序决定’的问题。” | 同伴运行并记录反馈。 |
| 29:00—39:00 | 规则故事会 | **教师说：**“每人或每组 90 秒：我的输入是……；我的规则优先级是……；我的边界测试是……；这条建议不适用于……。观众只问规则依据、遗漏信息或人工判断位置。” | 选 4—6 组展示。教师控制时间，记录高质量边界表述。 |
| 39:00—43:00 | 反思 | **教师说：**“写 150—250 字：我写的规则是……；我用哪组测试发现或确认……；规则遗漏了……；因此在……情况下应由人决定或补充信息。” | 独立写作。 |
| 43:00—45:00 | 提交与收束 | **教师说：**“请提交程序、流程图、测试表和反思。U2 的收获不是让程序替你做选择，而是让你看见：每个自动建议背后都有可质询的规则。” | 学生提交，教师汇总作品完成度。 |

## 三、试教后的复盘提示

与 U1 相同，U2 首轮试教后只确定一项 P0 修订。例如，若测试表普遍缺少组合输入，就补充一张“组合条件测试卡”；若学生无法解释优先级，就在第 2 课增加纸面流程排序。不要同时重写规则、代码、量规和检测。
