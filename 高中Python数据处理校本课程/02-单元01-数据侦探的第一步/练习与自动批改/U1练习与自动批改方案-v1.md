# U1 练习与本地自动批改方案 v1.0

## 一、设计目的

U1 的练习不以“刷语法题”为目的，而以逐步完成“变量表达 → 规则判断 → 一周数据汇总”的周数据小报为主线。自动批改只验证清晰、可观察的程序行为；它为学生提供快速反馈，为教师提供错误分布线索，但**不替代**对 IPO 知识图、调试过程、数据边界反思和同伴解释的评价。

练习按“必做—选做—挑战”分层。必做题让所有学生获得可运行经验；选做题让学生在不同输入下检验规则；挑战题引导学生封装函数、处理空数据和解释边界。自动批改只对必做与部分选做题给出反馈，挑战题由教师根据量规审阅。

## 二、练习任务与提交接口

学生只提交一个 `u1_submission.py` 文件。该文件必须**只定义函数，不包含顶层 `input()`、文件读写、网络访问或自动运行代码**，这样批改器才能稳定导入并测试函数。学生可另存一个自由发挥版的 `week_report.py` 用于展示；该展示程序不由自动批改器评分。

| 练习 | 学习目标 | 学生必须实现的函数 | 必测样例 | 自动反馈重点 |
|---|---|---|---|---|
| E1 变量与格式化 | 用变量组织主题和目标，并输出易读文本。 | `format_goal(topic, goal, unit)` | `("阅读", 30, "分钟")` | 是否正确拼接变量与文本。 |
| E2 条件判断 | 用 `if/else` 根据阈值给出状态。 | `daily_status(minutes, goal)` | `(30, 30)`、`(29, 30)` | 是否正确处理边界值 `minutes == goal`。 |
| E3 循环与汇总 | 遍历一周记录，计算总量、平均值、达标天数。 | `weekly_summary(records, goal)` | `[25,35,40,15,30,50,20]` | 是否正确累计、平均、计数；能否处理空列表。 |
| E4 挑战：连续达标 | 在循环中维护状态。 | `longest_goal_streak(records, goal)` | `[30,31,20,32,33]` | 连续值与中断后重置。 |

## 四、自动批改如何工作

批改器先用 Python 抽象语法树检查学生文件：只允许本单元所需的函数、变量、条件、`for` 循环、列表/字典、基本运算和少量安全内置函数；拒绝导入模块、文件读写、网络调用、顶层执行与不在白名单内的函数调用。通过静态检查后，批改器在**受超时控制的子进程**中导入学生文件，调用测试函数，逐题给出“通过/未通过/运行超时”的结果和下一步建议。

| 批改阶段 | 做什么 | 学生看到什么 |
|---|---|---|
| 接口检查 | 文件是否存在、能否解析、是否定义了要求的函数。 | “缺少 `weekly_summary`；请先保留函数名不变。” |
| 安全与规范检查 | 是否有 `import`、`open()`、顶层执行、未允许调用。 | “练习文件只保留函数定义；展示代码请放到另一个文件。” |
| 行为测试 | 向函数传入多组数据，比对返回值。 | “边界值 30 应判定为达标；检查 `>=` 是否写成 `>`。” |
| 诊断汇总 | 统计通过数与未通过类型。 | “已通过 6/8 项；优先检查空列表平均值。” |

## 五、运行方式

教师将 `grade_u1.py` 与学生提交的 `u1_submission.py` 放在同一文件夹，或用命令显式指向学生文件：

```bash
python grade_u1.py u1_submission.py
```

学生在编辑器终端中也可自行运行同一命令，先获得即时反馈，再提交展示版程序、IPO 图和反思。教师可要求学生把批改结果末尾的“通过数”和一条未通过反馈抄进调试日志，作为过程性评价的一部分。

## 六、安全边界与教师使用提示

本脚本是**课堂练习反馈工具，不是安全沙箱**。任何 Python 程序只要被执行，就不能在普通桌面环境中得到绝对安全隔离。因此，教师必须只在专用、权限受限的学生机或隔离的课堂账号中运行学生文件；不得用本脚本批改来自互联网或身份不明来源的代码；不要在存有敏感文件、管理员权限或网络共享凭据的教师电脑上直接执行未经审阅的提交。

脚本已经通过“只允许受限语法 + 拒绝导入/顶层执行 + 子进程超时”降低初学者练习中的误操作风险，但这不是针对恶意代码的安全保证。若学校需要批改不受信任的代码，应使用容器、虚拟机或学校统一的在线判题平台等真正隔离的执行环境。

## 七、与单元评价的关系

| 评价对象 | 推荐方式 | 自动批改是否覆盖 |
|---|---|---|
| E1—E3 基础函数行为 | 自动批改 + 学生修订。 | 覆盖。 |
| 周数据小报的可读性 | 同伴试运行与教师观察。 | 不覆盖。 |
| IPO 知识图 | 教师/同伴依据量规审阅。 | 不覆盖。 |
| 调试过程 | 调试日志、口头解释。 | 仅记录结果，不替代评价。 |
| 数据边界与责任 | 反思文本、展示追问。 | 不覆盖。 |

## 八、建议的课堂使用节奏

第 2、3、4 课时结束前各留 5—8 分钟运行一次批改器。学生应先阅读失败反馈、做出最小修改、再次运行，而不是向教师索要标准答案。第 5 课时只将自动批改视为“基础逻辑检查”，最终评价仍以能否讲清 IPO、解释数据结果和说明结论边界为准。
