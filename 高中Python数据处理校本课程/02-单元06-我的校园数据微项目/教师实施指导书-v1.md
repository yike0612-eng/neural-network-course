# U6《我的校园数据微项目》教师实施指导书 v1.0

## 一、单元定位与项目限额

U6 是 30 学时课程的收束单元。学生以小组为单位完成一个**小而完整**的校园数据微项目，并把 U1—U5 学到的“问题—数据—程序—结果—解释与边界”串成可展示、可复核、可修订的作品。该单元不是开放式“大数据竞赛”；教师应优先保障问题清晰、数据安全、处理链完整和解释负责任。

每组必须遵守六项限额：**一个小问题、一份批准数据、一项核心指标、一张主图、一条谨慎建议、一次 P0 修订**。若项目需要增加复杂模型、更多图表或真实个人数据，教师应将其改为课后选做，不能挤占核心证据时间。

> **固定课堂句式：**“先把问题缩小，再让数据说话；先证明流程连得起来，再解释结果；先写不能断言什么，再提出谨慎建议。”

## 二、课前准备与资源使用顺序

| 时点 | 教师使用资源 | 学生提交或留下的证据 | 教师控制点 |
|---|---|---|---|
| 课前 | `U6课时任务拆解与工作量优化重构方案-v1.md`；`学生学习单-v1.md`；`U6五课时教师逐字稿与分钟级时间表-v1.md` | 项目限额卡、角色卡、批准数据申请 | 只批准教学模拟、公开或脱敏数据；不允许收集个人敏感信息。 |
| 第26课 | 学习单任务与项目限额卡 | 小问题、核心指标、数据范围、角色分工 | 先冻结范围，再开始编码。 |
| 第27课 | 绿线代码骨架与数据字典模板 | 数据字典、清洗规则、问题日志样例 | 确认字段口径、缺失处理和责任边界。 |
| 第28课 | U6自动验收方案、模板与脚本 | 流水线运行结果、输入变化记录 | 让每组跑一次技术底线自检。 |
| 第29课 | 主图合同、同伴反馈表 | 主图、一页产品草稿、反馈记录 | 不让“美化图表”取代解释与复核。 |
| 第30课 | 结项任务书、三类证据量规、随堂检测 | 最终一页产品、60秒汇报、P0修订说明 | 结合自动结果和人工证据作组级评价。 |

## 三、五课时检查点与教师动作

| 课次 | 课堂检查点 | 必须看见的最小成果 | 若未达标，教师的减负动作 |
|---:|---|---|---|
| 26 | 范围冻结 | 一个可回答问题、一份批准数据、一项指标 | 把宽泛问题改写为“在给定范围内，类别 A 与 B 的某指标如何比较”。 |
| 27 | 绿线跑通 | 原始记录、清洗规则、有效记录、问题日志、一次汇总 | 删除非必要功能，只保留 `读入/整理—清洗—汇总—输出`。 |
| 28 | 质量与变化 | 原始/有效/问题记录数；一次输入变化测试；自动验收诊断 | 用模板的统一字段接口，不要求重新设计数据结构。 |
| 29 | 主图和故事 | 一张主图、图表合同、四句故事、同伴追问 | 图表不清晰时先补标题、单位、范围与分母，不新增图。 |
| 30 | 汇报与 P0 修订 | 一页产品、谨慎建议、边界、修订前后证据 | 仅修正最影响可信度的一项问题，并保留修订理由。 |

## 四、自动验收的正确用法

`自动验收与数据质量测试/grade_u6.py` 只检查学生另交的 `u6_submission.py` 中的统一接口：项目声明、清洗、问题日志、统计、原始保护、分组汇总、图表规格和输入变化。教师可把 `u6_submission_template.py` 作为绿线代码骨架，把 `u6_submission_reference.py` 作为本地回归测试样例。

运行命令为：

```bash
python grade_u6.py u6_submission.py
python grade_u6.py u6_submission.py --json-result u6_grade_result.json
```

该工具只适用于可信课堂提交，**不是安全沙箱**。自动分数仅构成小组产品层的技术底线证据，不生成个人排名，也不取代人工阅读项目说明、数据字典、展示页面和边界反思。

## 五、三类证据的组级评价

| 证据层 | 最低提交材料 | 教师判断标准 | 不能用自动分数替代的内容 |
|---|---|---|---|
| 产品层 | 绿线代码、数据处理核心、主图、一页产品 | 文件可打开、处理链可运行、主图对应汇总。 | 图表是否适合读者、展示是否清楚。 |
| 解释层 | 数据字典、清洗日志、核心指标定义、图表合同 | 每个数字能说明范围、规则、分母和数据去向。 | 问题是否真正可回答、口径是否适合项目语境。 |
| 责任层 | 批准数据声明、边界句、谨慎建议、同伴反馈、P0修订 | 不收集敏感个人信息；不夸大结果；能基于反馈修订。 | 建议是否适度、隐私与公共影响是否被认真考虑。 |

建议最终采用**组级描述性反馈**而非把自动评分单独换算为个人成绩。学生个人贡献可通过角色卡、过程观察和反思短文进行低风险记录。

## 六、常见风险与教师处置

| 风险 | 教师处置 |
|---|---|
| 问题范围过大，想分析“全校学习效率” | 回到六项限额，缩为一类模拟记录、一项指标、一次比较。 |
| 想收集姓名、班级、成绩或精确位置 | 立即停止收集，改用教师模拟数据、随机编号或公开脱敏数据。 |
| 小组只有一人写代码，其他人无证据 | 采用角色卡轮换：数据字典/代码检查/图表合同/边界审阅，并在学习单上签名留痕。 |
| 自动验收失败 | 先看诊断中的一项失败条件；用参考实现对照接口；不要直接替学生重写全部项目。 |
| 图表显示差异但学生直接写因果 | 强制改写为“在本数据范围内观察到……”，并补充“不能据此断言……”。 |

## 七、试教复盘建议

U6 试教后优先审查五类班级证据：项目是否按时冻结、绿线流水线是否跑通、自动验收失败集中在哪里、主图合同缺失什么、P0修订是否真的改变了可信度。一次迭代只处理一个最阻塞的共性问题。若主要障碍是设备或库环境，优先保持纯标准库与图表规格的基础路径；若主要障碍是项目范围，优先收紧项目限额而不是增加课时任务。
