# U6《我的校园数据微项目》自动验收与数据质量测试方案 v1.0

**适用场景：** 受控课堂中的教师验证与学生自检。  
**适用文件：** `u6_submission.py`，即学生在最终项目中另行提交的“可测试数据处理核心”；不替代小组的完整展示页面或主项目文件。  
**重要边界：** 本脚本**不是安全沙箱**。它只能在隔离的课堂目录中运行可信学生文件；不得用于来源不明的 Python 程序，也不得将自动分数当作个人高风险评价。

## 一、验收目标

U6 的项目成果不应因为每组主题不同而失去最低技术与数据质量标准。自动验收不评价项目是否“漂亮”或建议是否“宏大”，而检查每个项目是否具备如下可计算底线：

1. 学生能声明一个批准数据范围、核心指标、主图类型、边界和谨慎建议；
2. 原始记录经过清洗后能分流为有效记录和问题日志；
3. 原始输入不会被覆盖；
4. 汇总数字能追溯到有效记录和分组；
5. 改变一个允许修改的模拟输入时，汇总与图表规格会发生可解释变化；
6. 主图规格包含标题、轴/标签、单位、数据范围或边界提示。

## 二、提交接口

学生需要在 `u6_submission.py` 中实现以下五个函数。完整项目脚本可以继续保留自己的字段和图表代码；本文件只把项目数据映射为统一的课堂测试接口。

| 函数 | 输入 | 输出 | 用途 |
|---|---|---|---|
| `project_metadata()` | 无 | 字典 | 声明问题、批准数据、范围、指标、图表、单位、建议和边界。 |
| `clean_record(raw_record)` | 单条字典记录 | `{"ok": bool, "record": dict或None, "issue": dict或None}` | 将记录转为统一的 `category`、`value`、`period`，或记录问题原因。 |
| `process_records(raw_records)` | 原始记录列表 | `valid, issues, stats` | 批量清洗并产出记录去向统计。 |
| `group_summary(valid_records)` | 有效记录列表 | 分组字典 | 产出每类的有效数、总量和平均值。 |
| `build_chart_spec(summary)` | 分组汇总字典 | 图表规格字典 | 声明主图而不强制安装或运行绘图库。 |

### 统一记录口径

为了让不同项目都可接受相同的最低测试，`clean_record()` 的有效输出至少应包含：

```python
{"category": "东区", "value": 45, "period": "周一"}
```

这里的 `category` 可以映射为“空间”“日期类别”“规则输出”或其他教师批准的项目分类；`value` 可以映射为分钟数、有效记录数、次数或比例分子，但必须是非负数；`period` 可为空字符串，供时间型项目使用。学生的完整项目可保留更多字段，但不得删除这三个测试字段。

## 三、自动评分维度

| 维度 | 分值 | 自动通过条件 | 诊断方向 |
|---|---:|---|---|
| 项目声明 | 15 | 问题、范围、指标、图表、单位、建议、边界均非空；`approved_data=True`；`personal_data_collected=False`。 | 先明确项目范围和数据边界。 |
| 单条与批量清洗 | 25 | 能将两条有效记录转换为规范记录；空值、无效文本、负值进入问题日志。 | 检查字符串清理、类型转换、非负限制和返回结构。 |
| 质量日志 | 15 | 每条问题至少保留记录位置、字段、原始值和原因。 | 不要静默删除问题记录。 |
| 记录去向与原始保护 | 15 | 统计原始/有效/问题记录数；输入列表在处理后不变。 | 使用新结构，不覆盖原始记录。 |
| 分组汇总 | 15 | 每组有有效数、总量、平均值，且只基于有效记录。 | 检查分母和汇总对象。 |
| 图表规格与输入响应 | 15 | 图表有标题、标签、单位、类别和值；改变输入后汇总变化。 | 图表必须回应数据，而非固定文本。 |

总分为 100 分。**自动评分只覆盖产品层的技术底线和少量解释层口径，不评价责任层完整质量。**

## 四、不可自动替代的人工复核

教师必须结合 U6 学生学习单和结项任务书，人工检查下表内容。

| 人工复核项目 | 不能完全自动化的原因 |
|---|---|
| 问题是否真正小而可回答 | 文本非空并不代表问题范围合理。 |
| 数据字典是否与真实项目字段一致 | 统一测试接口只验证映射后的字段。 |
| 主图是否适合问题和读者 | 规格完整不等于图表选择正确。 |
| 一页数据产品是否解释清楚 | 自动脚本无法可靠评价表达逻辑和课堂展示。 |
| 同伴审阅与P0修订是否有依据 | 需要查看修订前后证据与审阅记录。 |
| 建议、伦理与边界是否负责任 | 需要教师阅读谨慎建议和边界声明。 |

## 五、教师运行方式

```bash
python grade_u6.py u6_submission.py
python grade_u6.py u6_submission.py --json-result u6_grade_result.json
```

参考提交文件应得到 100/100。学生模板不应通过全部测试；模板的诊断提示用于指导学生完成最小数据处理核心。运行前教师应确认：提交文件来自当前课堂、命令在隔离目录执行、没有真实学生敏感数据写入测试文件。

## 六、课堂使用节奏

| 时点 | 自动测试用途 | 教师人工任务 |
|---|---|---|
| 第28课 | 学生运行一次，检查绿线流水线和记录去向。 | 查看数据字典与两次输入变化测试。 |
| 第29课 | 教师抽查通过项目，确认主图规格依赖真实汇总。 | 审阅一页数据产品草稿与同伴反馈。 |
| 第30课 | 最终运行，保存 JSON 结果为技术底线证据。 | 根据三类证据量规审阅解释、责任与P0修订。 |

> **本工具的正确用途是帮助学生发现“输入、规则、输出是否相连”，而不是把数据项目压缩成一个数字分数。**
