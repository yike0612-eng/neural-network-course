# 《用 Python 读懂日常数据》课程资源使用说明 v1.0

## 一、离线部署

本课程第一版资源以 Markdown、Python 源文件和本地模拟数据为主，不依赖在线账户或云端接口。教师将完整文件夹复制到教师机与学生机即可使用；推荐在每台学生机上使用 Python 3.10+ 及 Thonny、IDLE 或 VS Code 之一。若学校采取公共机房镜像，建议将 Python 编辑器、浏览器和资源文件夹同时写入镜像，避免上课时临时安装。

| 使用场景 | 建议做法 | 不建议做法 |
|---|---|---|
| 无网络机房 | 使用本地 `.py` 文件、脱敏 CSV 与静态学习单。 | 在课堂核心任务中依赖临时注册、网页验证码或外部 API。 |
| 网络不稳定机房 | 将云端资料预先下载并准备本地备份。 | 把唯一的代码、数据或说明放在在线协作文档中。 |
| 学生自带设备 | 提供已测试的 Python 版本和“打开—运行—保存”图文指引。 | 要求学生自行选择复杂开发环境且不给最小配置方案。 |

## 二、数据责任规则

课程优先使用三类数据：公开数据、教师提供的脱敏数据、明确标记为教学模拟的合成数据。学生项目不得收集或展示同学的姓名、联系方式、精确位置、成绩、健康信息、家庭信息或财务明细。涉及问卷时，必须经教师同意，采取匿名、自愿、最小必要原则；任何学生都可以选择不提供个人数据而使用模拟数据完成任务。

每份数据作品必须附上四句数据说明：数据从哪里来；每个字段代表什么；做了哪些处理；结论不能说明什么。教师评价时，应把这四句说明视为数据素养的一部分，而不是附加装饰。

## 三、文件与版本命名

资源文件以“名称-版本”命名，例如 `教师指导书-v1.md`。学生提交文件夹以“班级_姓名_单元”命名，例如 `高一3班_李明_U1`。迭代资源时，不覆盖原始可用版本；应在文件开头简要记录版本号、修改日期、修改原因和适用范围。

## 四、课堂运行前检查

| 检查项目 | 最低标准 |
|---|---|
| 编辑器 | 能新建、保存、运行 `.py` 文件并看到控制台输出。 |
| 文件权限 | 学生能在个人文件夹保存副本，不会修改教师原件。 |
| 中文显示 | 控制台与编辑器正常显示中文文本。 |
| 示例代码 | 教师在至少两台不同电脑上运行起始代码和参考实现。 |
| 数据安全 | 课堂使用数据已标注来源/模拟性质，未含敏感个人信息。 |
| 备份方案 | 教师机保留 U 盘或本地备用副本。 |

## 五、资源迭代原则

资源的每次修改都应回答三个问题：它服务于哪个学习目标？学生能产生什么可观察证据？它是否降低了而不是增加了课堂部署负担？若新增功能只带来页面装饰、语法负担或外部依赖，而没有改善理解、反馈或表达，则不建议纳入普惠版。
