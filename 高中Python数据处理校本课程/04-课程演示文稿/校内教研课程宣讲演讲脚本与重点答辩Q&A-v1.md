# 高中 Python 数据处理校本课程
# 校内教研课程宣讲演讲脚本与重点答辩 Q&A v1.0

**适用场景：** 校内课程立项、教研组说课、信息技术教师集备、试教启动会。  
**建议总时长：** 10—12 分钟宣讲；8—15 分钟问答。  
**配套材料：** 《从日常问题到负责任的建议：高中 Python 数据处理校本课程说课》10页演示文稿。

> **宣讲总主张：** 这不是一门“把 Python 语法讲完”的课程，而是一门帮助学生把日常问题处理成清楚、可信且有边界的数据结论的通识课程。

## 二、逐页演讲脚本

### 第1页｜从日常问题到负责任的建议

各位老师好。今天汇报的是一门面向高一、高二学生的 30 学时校本课程——《用 Python 读懂日常数据》。我们希望学生在课程结束时，获得的不只是几条 Python 语法，而是一种能够迁移到日常生活与学习中的数据思维：面对一个问题，知道先界定问题；面对一份数据，知道先检查范围与质量；写出程序后，知道结果需要解释，也需要说明边界。

因此，本课程的主线被固定为“问题、数据、程序、结果、解释与边界”。这条链路贯穿六个单元，尤其在 U4 到 U6 形成课程后半程最有价值的能力闭环：让数据可信，让表达可信，让行动可信。

### 第2页｜不仅是编程，更是现代数据素养

我们观察到，学生在入门 Python 时常常可以完成变量、循环或条件判断，但一旦面对真实表格，容易不知道哪一列可用、空白意味着什么、为什么同一组数字可以画出不同观感的图。更常见的问题是，学生得到一个平均数或一张图后，很容易把一次有限观察说成确定结论。

所以，这门课程把 Python 放在数据素养的框架中。我们不追求让学生记住更多库函数，而是让他们学会用程序把问题变成证据，并用负责任的语言把证据表达出来。这里的“负责任”包括数据来源合规、保留清洗规则、说明分母、不夸大图表差异，也包括承认“这个数据还不能支持什么”。

### 第3页｜课程总体蓝图：从认知到创造

课程共 30 学时、六个单元，每单元 5 学时。U1 到 U3 建立编程和问题意识，学生从运行第一段程序，到把规则写进程序，再到用列表与字典整理多条记录。U4 到 U6 则进入可信数据产品阶段。

认知上，课程不是一次性跳到项目，而是从记忆和理解，逐步走向应用、分析、评价和创造。U4 让学生判断数据能否进入分析；U5 让学生判断图表表达是否清楚；U6 再让学生把这些能力整合为一个小而完整的数据微项目。这样的阶梯让高一和高二学生都能够在基础任务中成功，同时在验证、表达和协作方面获得可选择的挑战。

### 第4页｜U4：数据能不能进入分析？

U4 是后半程的技术和方法底座。它把学生从程序中的列表与字典带到 CSV 表格，让他们第一次面对缺失值、文本数字、可能重复和字段口径等真实数据问题。

这里最重要的不是“用一条命令把表格读进来”，而是形成三条规范。第一，清洗规则要先于代码：空白不一定是零，重复也不等于可以直接删除。第二，原始记录不可覆盖，问题记录要留下日志，保留字段、原始值和原因。第三，任何统计结果都必须说明记录去向，包括原始行数、有效行数、问题行数，以及平均值的分母。

这一步让学生从“程序算出了数字”进阶到“我可以说明数字来自哪些记录、哪些记录未进入分析，以及为什么”。这也是 U5 图表口径和 U6 数据字典的直接来源。

### 第5页｜U5：分析结果能否被正确理解？

如果说 U4 解决的是数据可信，那么 U5 解决的是表达可信。我们没有把 U5 设计成单纯的 `matplotlib` 操作课，而是用“图表合同”把图表选择、数据范围、统计量、分母、标题单位和误导风险全部显性化。

学生在画图或分析预制图前，必须回答：这张图要回答什么问题？使用了哪些有效记录？为什么选择柱状图或折线图？读者可能误解什么？如果改变一条输入，图形和解释应如何变化？这样，图表不再只是“输出漂亮图片”，而是可检验的证据表达。

同时，课程设置代码绘图与预制图分析双路径。设备能够运行绘图库时，学生可以写代码出图；当机房环境受限时，学生仍可以围绕同一份图表合同完成高阶解释任务。这样做不是降低要求，而是把技术环境差异与学习目标分开处理。

### 第6页｜U6：小而完整的责任性创造

U6 是整门课程的收束。它不增加新的核心语法，而是让学生把前五个单元的能力整合为一个校园数据微项目。为了防止项目变成“题目很大、作品很空”或“少数学生完成、其他学生旁观”，我们为项目设置六项限额：一个小问题、一份批准数据、一项核心指标、一张主图、一条谨慎建议、一次 P0 修订。

同时，五个课时有明确检查点。第26课先冻结范围；第27课只求绿线流水线跑通；第28课检查数据质量与输入变化；第29课形成主图与数据故事；第30课完成展示、同伴质询和一次有依据的修订。教师的支持原则是优先删减不必要功能，先保护完整的证据链。

这样的项目式学习并不追求宏大结论。学生最终提出的是小范围、低风险、可尝试、可复盘的建议，并且必须写明“数据支持什么、不能支持什么”。

### 第7页｜产品层、解释层、责任层

课程评价使用三类证据。产品层回答“程序是否能跑通、图表是否有基本要素”；解释层回答“这个数字从哪里来、字段口径和分母是什么、为什么这样选图”；责任层回答“是否使用敏感数据、是否存在误导风险、是否根据同伴反馈修订、建议是否超出了数据边界”。

这一框架能够避免两种极端。一种是只看代码运行，不看学生是否理解；另一种是只看作品好看，不看数据处理是否可复核。自动评分与验收脚本只用于产品层的技术底线诊断，且只在受控课堂中运行可信代码。它们不是安全沙箱，更不能被转换成学生个人排名。

### 第8页｜六维量规与综合评价

U6 结项项目使用六维量规：问题界定占 15%，数据口径与质量占 20%，处理流水线占 20%，证据与表达占 20%，复核与迭代占 15%，数据责任与协作占 10%。可以看到，课程并没有把代码当作唯一标准；代码与数据处理合起来占 40%，而解释、复核、责任与协作同样构成不可替代的部分。

评价以组级描述性反馈为主。每位学生通过角色卡、过程记录和个人复盘保留贡献证据，但不通过匿名检测或自动分数推断能力高低。我们希望形成的是低风险试错环境：学生可以修改代码、承认数据问题、接受质询，而不是为了避免扣分而隐藏过程中的困难。

### 第9页｜完整配套，即刻开课

课程实施方面，我们已经提供了完整资源。每个单元都有教师指导书或实施指导书、分钟级逐字稿、学生学习单、随堂检测、结项任务书，以及可用于可信课堂提交的自动评分或验收工具。U4 到 U6 还配有数据质量检查与项目验收方案。

环境上，课程以普通 Windows 机房、Python 3.10+ 和标准库为基础路径。U4 的 CSV 读取使用标准库 `csv`，不把 `pandas` 作为最低要求；U5 在绘图库不可用时提供预制图分析路径。因此，学校不需要先建设复杂平台，便可以从 U1 或 U4 的一个小单元开始试教。

实施上，我们建议先进行一次窄范围试教，并只根据一个最明显的班级证据做一项 P0 修订。例如，若学生集中卡在路径问题，就先补环境自检；若学生集中混淆分母，就先加强图表合同，而不是一次性重写所有资源。

### 第10页｜让数据成为看见世界的可靠透镜

最后，我们希望学生离开这门课程时，不只会说“我会 Python”，而是能够更有根据地看待身边的数字、表格和图表。他们能够把一个日常问题缩小到可回答的范围，使用合规数据和程序形成证据，解释结果的来源，也承认结论的边界。

从这个意义上说，Python 是一种工具，数据素养是一种能力，而负责任地作出判断才是课程真正希望培养的品格。我们欢迎各位老师参与试教、提出修订意见，共同把这门课程做成学生看见世界、理解世界的一副可靠透镜。谢谢各位。

## 三、重点答辩 Q&A

### A. 课程定位与必要性

| 可能提问 | 建议回答 |
|---|---|
| **Q1：学校已经有信息技术课，为什么还要单独开这门校本课程？** | 现有课程通常覆盖基础编程或工具使用，而本课程聚焦“用 Python 完成一次可信的数据推理”。它把编程、数据处理、图表表达和数据责任放在同一条证据链上，填补了“会写程序”与“能对数据作出谨慎解释”之间的空档。课程也可作为现有信息技术课的拓展模块，而不必替代原有课程。 |
| **Q2：高一、高二混班或零基础学生能完成吗？** | 可以。U1—U3采用骨架代码和小步反馈保证基础任务可完成；U4—U6用“必做—选做—挑战”分层。高二学生不需要获得更多题量，而可以承担函数封装、数据质量审查、图表比较或项目技术负责人等更高层职责。 |
| **Q3：为什么强调‘日常问题’，而不是让学生做更前沿的AI或大数据项目？** | 30学时内，学生最需要形成的是完整、可复核的基础能力。日常低风险问题更容易控制数据来源、隐私边界与任务范围，也更利于学生完成从问题到建议的完整循环。复杂AI项目可作为后续拓展，不应挤占数据素养主线。 |

### B. U4—U6进阶与教学设计

| 可能提问 | 建议回答 |
|---|---|
| **Q4：U4、U5、U6各自的区别是什么？会不会内容重复？** | 三个单元处理的是不同的可信度问题。U4关注“数据是否可信进入分析”，核心是字段、清洗与记录去向；U5关注“表达是否可信”，核心是分母、图表合同和误导检查；U6关注“行动是否可信”，核心是小问题、合规数据、同伴复核和P0修订。它们共享同一证据链，但每个单元解决不同环节。 |
| **Q5：U5为什么要设置代码绘图和预制图分析两条路径？** | 两条路径的学习目标完全一致，都是完成图表合同、数据回溯、误导检查和边界说明。不同的是，代码路径多一层技术实践；预制图路径在环境受限时保障学生仍能完成高阶解释任务。这样既不降低目标，也不把设备差异变成学习评价差异。 |
| **Q6：U6的六项限额会不会限制学生创造力？** | 限额保护的是核心创造。高中生第一次做数据项目常见问题是题目过大、数据无边界、图很多但没有结论。六项限额保证每组完成一个可复核的最小产品；完成最低版本后，课程仍提供函数封装、多版本图表比较、匿名化方案等挑战任务。 |
| **Q7：5个课时是否足够完成U6项目？** | 足够完成“微项目”，但不适合完成大型研究。关键在于第26课冻结范围、第27课先跑通绿线、第28课确认变化测试。若课堂出现困难，教师优先删除非必要功能，而不牺牲数据字典、清洗日志、边界句和一次修订这些核心证据。 |

### C. 数据安全、评价与自动化工具

| 可能提问 | 建议回答 |
|---|---|
| **Q8：学生数据从哪里来？会不会涉及隐私？** | 课程优先使用教学模拟数据、公开数据或教师审核的脱敏数据。禁止采集姓名、学号、成绩、健康、联系方式、精确位置和可识别个人行为记录。若学生提出新题目，教师必须先审查数据来源、最小必要性和风险；不合规就改为模拟数据或拒绝收集。 |
| **Q9：自动评分是否会把评价变成‘机器打分’？** | 不会。自动评分只检查可编码的产品层底线，例如函数接口、数据清洗、问题日志、原始数据保护、汇总结构和输入变化响应。问题是否合理、图表是否适合、建议是否越界、伦理说明是否具体，必须由教师人工评价。 |
| **Q10：自动验收脚本是否安全？** | 不是安全沙箱。它只应在受控课堂目录中运行当前班级的可信提交，不能运行来源不明的代码。课程材料中已经明确了这一边界，并建议教师避免在公共共享目录、个人敏感数据目录或未知文件上执行脚本。 |
| **Q11：如何防止学生搭便车或只有一人写代码？** | U6通过角色卡把问题与口径、数据处理、图表与表达、复核与责任分别留痕。角色可以轮换，但每位学生要提交个人工作证据与150—250字复盘。最终采用组级描述性反馈，同时保留过程观察，而不是单靠成品推断个人贡献。 |
| **Q12：是否会根据匿名随堂检测给学生排序？** | 不会。检测使用随机编号，分析脚本只输出班级层面和题目层面的错因汇总。较低正确率被解释为检查任务设计、时间安排和支架是否需要调整的信号，而不是为学生贴标签。 |

### D. 实施条件与教研推进

| 可能提问 | 建议回答 |
|---|---|
| **Q13：没有网络、没有pandas或matplotlib，能开课吗？** | 能。课程按普通 Windows 机房和 Python 标准库设计。U4用`csv`作为基础路径；U5在没有绘图库时采用预制图分析路径；U6的技术验收以统一函数接口与图表规格检查为基础，不强制额外安装库。 |
| **Q14：教师需要具备多高的Python水平？** | 能运行、修改和解释基础Python脚本即可启动。大礼包提供分钟级逐字稿、起始/参考代码、自动诊断和即时调整建议。建议第一次只做U1或选一个U4—U5班级试教，由教研组共同复盘，再逐步扩展。 |
| **Q15：试教以后怎么改，避免不断大修？** | 遵循“单一P0修订”原则。先收集一个清楚的班级证据，例如路径故障、字符串/数字混淆、分母遗漏或项目范围失控，然后只改进最阻塞的一处资源。下一轮再验证该改动是否有效。 |
| **Q16：本课程如何与AI教育、综合实践或劳动教育结合？** | 可作为AI教育的底座：学生先理解数据、证据与边界，再进入模型和智能工具。也可与综合实践结合，以公共设施、阅读空间或学习资源等低风险主题做小规模观察。但须保持课程边界：不得以学生隐私数据支撑“智能化”展示。 |
