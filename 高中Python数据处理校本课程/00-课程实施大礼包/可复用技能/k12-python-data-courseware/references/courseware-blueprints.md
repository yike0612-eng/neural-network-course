# 高中 Python 数据处理课程资源蓝图

仅在创建或扩展高一、高二 Python 通识与数据处理校本课程资源时读取本文件。

## 1. 课程总体蓝图

课程总体蓝图至少写清：对象与课时、课程主线、6 个单元的驱动问题与关键产出、每单元 5×45 分钟的学习路径、三个成果（程序/知识图/反思）、分层任务、评价结构、离线部署与数据安全边界。用“问题 → 数据 → 程序 → 结果 → 解释与边界”组织能力进阶，不按语法目录堆叠。

| 单元 | 核心能力 | 建议产品 |
|---|---|---|
| U1 | 变量、条件、循环、数据解释 | 周数据小报 |
| U2 | 布尔逻辑、分支、函数、边界测试 | 校园任务助手 |
| U3 | 列表、字典、批量清洗、质量日志 | 数据整理器 |
| U4 | CSV、筛选、分组统计、可信表格 | 清洗与统计脚本 |
| U5 | 图表、统计解释、防误导表达 | 数据故事页 |
| U6 | 问题定义、数据字典、综合展示 | 小组数据微项目 |

## 2. 5×45 分钟单元设计

每个单元必须给出以下内容：单元定位、最终产品、学习目标与评价证据、教学模拟数据与数据边界、关键代码、5 个课时的逐时流程、常见错误及追问、分层支持、评价量规。每课至少设置一个形成性检查，如预测输出、退出卡、边界测试表、同伴试运行或调试日志。

> 先让学生手动预测和解释，再运行代码。不要将“成功运行”直接视为“理解”。

## 3. 学生学习单

学习单应按任务序列组织：情境与输入 → 纸面预测 → 代码补全或改造 → 测试与调试记录 → 知识图 → 同伴反馈 → 反思 → 提交清单 → 挑战任务。避免只给练习题；必须让学生写下预期、实际输出和最小修改。

## 4. 本地自动批改

自动批改只面向基础函数行为，不能替代作品、知识图、反思和协作评价。要求学生提交仅含函数定义的文件；展示版程序另存。设计顺序：

1. 明确稳定函数名、参数、返回值和测试规则。
2. 设计普通、边界、组合、空值或异常输入测试。
3. 静态检查中拒绝导入、顶层执行、文件/网络操作与未允许调用。
4. 在超时控制的独立子进程中调用提交函数。
5. 输出逐项可操作反馈；提示学生先修改第一项失败。
6. 明确声明：本地批改器不是安全沙箱，只能在受控课堂设备中处理可信代码。

## 5. 汇报演示文稿与演讲稿

默认制作不超过 12 页的学校汇报演示文稿。推荐结构：封面；课程定位；三类成果；设计依据；30 学时能力链；六单元概览；U1；U2；U3—U4；U5—U6；评价；试教与迭代。每页只表达一个结论，正文不超过 3—4 点。同步输出逐页演讲稿，按 12—18 分钟控制长度。

## 6. 质量检查

交付前检查以下事项：

| 检查项 | 通过条件 |
|---|---|
| 课时 | 总课时和每单元课时相加一致。 |
| 对齐 | 目标、课堂活动、评价证据和提交物相互对应。 |
| 数据责任 | 只用教学模拟或已授权、去标识化数据；不采集学生敏感信息。 |
| 代码 | 起始代码与参考实现可编译、可运行；自动批改参考提交通过。 |
| 批改安全 | 说明受控环境边界，不宣称普通 Python 执行具有绝对隔离。 |
| 演示文稿 | 页数符合限制，文本与演讲稿一致，完成后正式展示。 |
