# 单元首轮试教、检测与汇报规范

仅在准备单元试教、课堂检测、结果复盘或校内试教汇报时读取本文件。

## 1. 收束试教范围

首轮只验证一个 5×45 分钟单元、一个常规班级和一个明确的最小学习闭环。不要同时开发后续单元、改写总体课程或把自动批改当作终结性评分。试教前定义：课程要验证什么、哪些数据不收集、每课保留哪一项最小证据、试教后由哪些信号触发一项 P0 修订。

## 2. 教师逐字稿与分钟表

为每课给出总计恰为 45 分钟的时间段。每段应包含：教师可直接说的关键提示、学生的预期动作、形成性检查，以及必要时的即时调整规则。固定课堂循环是：预测 → 运行 → 比较 → 最小修改；涉及循环时加入手算追踪；涉及作品时加入同伴试运行。

逐字稿应稳定关键概念、数据安全边界与转场，不应把教师变成照读机器。避免在设备故障时临时扩展技术内容；先改用同伴机、纸面预测或手算活动，恢复学习节奏。

## 3. 匿名随堂检测

选择 8—12 题，覆盖单元最小目标，而不是覆盖所有术语。题目应包含程序行为预测、边界情况、手算追踪、输入/处理/输出解释、调试步骤和数据结论边界。学生答卷只使用匿名响应编号；不得收集姓名、学号、成绩、联系方式或敏感信息。

将答案映射到知识点与教师复盘动作。使用以下工作阈值：正确率 ≥ 80% 为“稳定”，60%—79% 为“需巩固”，<60% 为“优先修订”。这些是资源改进信号，不是高风险学生标签。

## 4. 汇总与解释

使用 `scripts/analyze_anonymous_quiz.py`，并以 `templates/anonymous_quiz_config_template.json` 创建题目配置。该脚本只输出班级、题目和知识点层面的汇总。运行前确认输入 CSV 有 `response_id` 和配置中的所有题目列；输出后将题目结果与课堂观察、作品完成度、环境日志共同解释。不要生成学生排名、单人分数或基于单项测验的自动推进结论。

## 5. 10页试教汇报结构

默认用 10 页：封面；项目已有资产与缺口；课程初心；为何收束到当前单元；试教范围；五课时最小闭环；教师实施保障；三类成果与评价；匿名检测与证据采集；试教后的单一 P0 决策。结论必须是可执行的下一步，不是课程资源清单。

## 6. 复盘决策

试教后只选择一项 P0 修改。优先选择同时获得课堂观察、作品证据和检测证据支持的具体问题，例如增加循环变量追踪表。不要一次修改目标、学习单、代码、量规、数据和全部讲稿。

## 7. 单元结项数据处理项目

为基础单元设计一个小型结项项目，而不是提前引入后续单元的复杂工具。任务书必须给出一个明确、低风险的模拟数据情境；固定字段口径；一个可回答的问题；最低可运行版本；至少两组“改一条数据/改一个阈值”的测试；IPO 图；基于证据的发现与结论边界；同伴试运行；基础、选做与挑战任务。不要使用真实可识别的学生个人数据，也不要将有限记录推断为成绩、健康、纪律或长期能力。

## 8. 逐页演讲脚本

当已有校内汇报大纲时，为每页写一段可口头呈现的演讲稿，并标出建议时间、转场与要强调的单一结论。10 页汇报通常控制在 8—12 分钟。封面说明审阅目的；中间页依次解释现状、课程初心、为何收束试教、实施与证据设计；末页只提出一个明确决策。不要把幻灯片文字逐条重复为讲稿；用讲稿解释“为什么现在这样做”。
