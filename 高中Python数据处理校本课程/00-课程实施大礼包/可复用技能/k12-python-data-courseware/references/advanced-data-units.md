# U4—U6：可信数据产品后半程

在 30 学时高中 Python 数据素养课程中，将 U4—U6 组织为连续的可信数据产品链：**U4 让数据可信，U5 让表达可信，U6 让行动可信**。不要把三个单元写成孤立的“CSV课、绘图课、项目课”。

## U4：CSV 与数据质量

使用标准库 `csv.DictReader` 作为最低路径。先明确字段口径和清洗规则，再写代码。保留原始记录；将有效记录与问题记录分流；问题日志至少包含记录位置、字段、原始值、原因；统计原始数、有效数、问题数；所有平均数或比例均说明有效分母。将 `pandas` 视为选做扩展，不得成为最低要求。

评价时要求产品层（脚本与汇总可运行）、解释层（字段字典、清洗规则、记录去向）和责任层（不把潜在重复当作已证实错误、不将模拟数据扩大解释）。

## U5：图表合同与双路径

在绘图前要求学生填写“图表合同”。合同至少包括：问题、数据范围与有效口径、统计量与分母、图表类型选择理由、标题/标签/单位、读者可能误读处、一次输入变化预测与核对。

准备两条等价学习路径：

- **代码路径**：在已验证环境中用图形库或基础绘图代码生成图表。
- **预制图路径**：当扩展库不可用时，用教师提供图表完成相同的图表合同、数据回溯、误导检查和边界说明。

两条路径使用同一解释层和责任层量规。不要因机房库环境差异降低图表选择、分母、误导检查或边界表达要求。明确指出非零坐标轴不必然错误；判断必须结合图表目的、标注、数据范围与读者可能获得的印象。

## U6：六项限额微项目

将项目限制为一个小问题、一份批准数据、一项核心指标、一张主图、一条谨慎建议、一次 P0 修订。使用五个检查点：

1. 范围冻结：对象、范围、指标、成功标准、角色和数据来源齐全。
2. 绿线跑通：读入/整理、清洗、汇总、输出链条可运行。
3. 质量与变化：报告原始/有效/问题记录数，完成一次输入变化测试。
4. 主图与故事：完成图表合同、四句故事和同伴追问。
5. 汇报与修订：完成一页产品、边界、谨慎建议与一次有证据的 P0 修订。

小组角色至少覆盖问题与口径、数据处理、图表与表达、复核与责任；允许轮换，但为每位学生保留角色证据与低风险复盘。只使用教学模拟、公开、授权或脱敏数据；禁止处理可识别学生的敏感信息。

## U6 自动验收边界

若提供自动验收器，将统一接口限定为项目元数据、单条清洗、批量处理、分组汇总与图表规格。测试项目声明、有效与问题分流、问题日志字段、原始记录保护、记录统计、分组汇总和输入变化响应。输出维度诊断，不只输出分数。

明确：自动验收只能验证产品层技术底线；不是安全沙箱；仅在受控课堂目录运行可信提交；不生成个人排名；不代替教师评价问题质量、图表选择、建议风险和伦理声明。

## U4—U6 评价与对外沟通

使用三类证据评价：产品层检查可运行和要素完整，解释层检查口径、规则、分母和数据去向，责任层检查隐私、误导风险、边界、同伴复核和修订。

在校内说课时，用“数据可信吗—表达清楚吗—建议负责任吗”串起 U4—U6。展示项目的技术自检时，同时说明自动工具的边界。对外宣传不承诺用数据评价学生能力，不宣传“监测学生行为”；强调低风险、可复核、可解释和可迭代的数据素养实践。
