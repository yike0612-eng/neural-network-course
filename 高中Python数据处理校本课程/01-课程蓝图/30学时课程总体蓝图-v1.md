# 《用 Python 读懂日常数据》校本课程总体蓝图 v1.0

**适用对象：** 高一、高二学生，默认零基础或仅有零散编程体验。  
**课程性质：** 日常 Python 通识入门与数据处理校本课程。  
**建议课时：** 30 学时，每学时 45 分钟；建议每周 2 学时，连续实施 15 周。  
**运行环境：** Windows 普通机房；Python 3.10+；推荐使用 Thonny、IDLE 或 VS Code 之一。第 4—6 单元可使用本地 Jupyter Notebook 与 `pandas`、`matplotlib`；学校无法预装扩展库时，使用标准库 `csv` 作为基础路径。

## 一、课程定位

本课程不是“把 Python 语法讲完”的编程课，而是一门帮助学生**把日常问题转化为可处理的数据问题、用 Python 形成证据、再用负责任的方式表达结论**的通识课程。课程以校园生活、公共服务、个人习惯和兴趣活动中的低风险问题为情境，例如“图书馆何时更忙”“班级阅读偏好如何呈现”“校园节能倡议应关注哪些数据”。学生将在真实但脱敏、公开或教学模拟的数据中完成从提问、整理、计算、可视化到解释的完整小循环。

课程以项目既有的“智能产品、知识图、反思报告”成果结构为统一出口，但将“智能产品”具体化为**可运行的数据处理程序或数据故事作品**。神经网络微课作为后续人工智能拓展资源保留，不挤占本课程前 30 学时的 Python 与数据素养主线。

> **课程一句话目标：** 让每位学生都能用 Python 把一个日常问题处理成清楚、可信且有边界的数据结论。

## 二、设计依据与课程原则

本稿将“俊杰”按尚俊杰教授理解。其研究聚焦学习科学、游戏化学习、人工智能教育与教育数字化，强调让学习更科学、更快乐、更有效。[1] 修订版布鲁姆分类法将认知过程组织为“记忆、理解、应用、分析、评价、创造”，并强调以可观察的动词界定学习目标，使活动、目标与评价对齐。[2] [3]

| 设计依据 | 在本课程中的转化 | 可观察证据 |
|---|---|---|
| 布鲁姆：由基础到高阶的认知进阶 | 以“识别与解释—编写与运行—拆解与比较—判断与创造”组织六个单元，而非按语法目录堆叠。 | 程序运行记录、口头解释、代码注释、数据图表、项目答辩。 |
| 布鲁姆：目标—活动—评价对齐 | 每个课时都有可操作动词、课堂任务和对应的形成性检查；终结性评价不只考术语回忆。 | 退出卡、调试卡、随堂任务、单元作品和量规。 |
| 尚俊杰：学习科学与游戏化学习 | 采用“数据侦探任务线”、低风险试错、即时反馈、角色协作、关卡递进和可选择挑战，但不把积分排名当作学习目标。 | 小组任务单、调试记录、挑战任务选择、同伴反馈与作品迭代。 |
| 项目既有“三个成果”结构 | 每一单元交付一个可运行程序/分析产品、一张知识图、一次基于证据的反思。 | 单元成果包与统一评价量规。 |

## 三、课程总目标

完成 30 学时学习后，学生应能在给定或自选的日常数据情境中完成以下表现。

| 维度 | 课程目标 | 对应布鲁姆层级 | 达成证据 |
|---|---|---|---|
| 数据意识 | 识别一个问题中的对象、字段、数据来源、口径与隐私边界，说明数据不能直接等同于结论。 | 理解、分析、评价 | 问题拆解卡、数据说明、数据责任反思。 |
| Python 基础 | 使用变量、基本数据类型、输入输出、条件、循环、列表、字典、函数和文件操作编写短程序。 | 记忆、理解、应用 | 代码运行结果、调试日志、随堂任务。 |
| 数据处理 | 使用 Python 对结构化数据完成读取、清洗、统计、筛选、分组汇总和基础可视化。 | 应用、分析 | Notebook 或 `.py` 程序、处理后的数据表、图表。 |
| 计算思维 | 将日常任务拆分为输入、处理、输出，能用伪代码、流程图或函数模块解释程序。 | 理解、分析 | 知识图、流程图、代码注释。 |
| 证据表达 | 根据图表和统计量解释发现，区分事实、推断与建议，并说明结论的不确定性。 | 分析、评价 | 数据故事页、口头展示、同伴提问回应。 |
| 创造与责任 | 以小组形式完成一件数据产品，恰当处理来源、匿名、授权和图表误导等问题。 | 评价、创造 | 期末项目、展示记录、伦理与改进说明。 |

## 四、30 学时单元结构

课程共六个单元，每单元 5 学时。前两单元建立编程与问题意识，第三、四单元进入数据结构和文件数据处理，第五单元强化证据表达，第六单元完成综合创作。每个单元既有基础任务，也提供挑战任务；高二学生可优先承担函数封装、数据质量审查、可视化比较或项目组技术负责人角色，而无需另行分出一套课程。

| 单元 | 学时 | 驱动问题 | 核心 Python / 数据概念 | 认知重点 | 三个成果 |
|---|---:|---|---|---|---|
| U1 数据侦探的第一步 | 5 | 一周阅读、运动或消费记录能告诉我们什么？ | 运行程序、`print()`、变量、数值/字符串、列表、条件、循环、调试。 | 记忆→理解→应用 | 周数据小报程序；“输入—处理—输出”图；第一次调试与数据边界反思。 |
| U2 让程序替我做选择 | 5 | 如何让程序按规则自动判断并重复处理任务？ | 布尔表达式、分支、嵌套、`for`/`while`、函数、测试样例。 | 理解→应用→分析 | 校园任务助手；决策流程图；规则公平性反思。 |
| U3 用列表和字典整理生活信息 | 5 | 零散记录怎样变成可查询、可汇总的数据？ | 列表、字典、遍历、累加、最大最小、简单排序、函数封装。 | 应用→分析 | 数据整理器；数据结构关系图；字段口径反思。 |
| U4 从 CSV 到可信表格 | 5 | 面对一份原始表格，如何发现错误并得到可用数据？ | 文件路径、`csv` / `pandas`、缺失值、重复值、类型转换、筛选、汇总。 | 应用→分析→评价 | CSV 清洗与统计脚本；数据清洗流程图；数据质量说明。 |
| U5 让图表说清楚 | 5 | 如何用合适的图表表达发现，而不误导读者？ | 平均数、中位数、比例、分组统计、柱状图/折线图/饼图的适用边界、`matplotlib`。 | 分析→评价 | 可视化数据故事页；图表选择图；图表误导检查单。 |
| U6 我的校园数据微项目 | 5 | 我们能为一个日常问题做出怎样的、负责任的数据建议？ | 问题界定、数据字典、处理流水线、协作、展示、迭代。 | 评价→创造 | 小组数据产品；项目知识图；项目复盘与伦理声明。 |

## 六、教与学实施机制

### 6.1 每学时的课堂节奏

每个 45 分钟课时采用“引入—探究—实践—反馈—复盘”的稳定节奏。前 5 分钟用一个日常现象、输出预测或错误代码形成认知冲突；10 分钟用小例子演示新概念；20 分钟完成一项可运行的任务；5 分钟以同伴测试、自动检查或教师巡视提供即时反馈；最后 5 分钟写退出卡，记录“我今天能做什么、还不明白什么、数据上要注意什么”。这种节奏服务于学生的注意、练习和反思，不以追赶讲授进度为目的。

### 6.2 分层支持

基础任务保证所有学生都能运行、修改、解释一段程序；进阶任务强调封装函数、处理异常、增加字段或比较不同算法；开放任务引导学生提出新的数据问题。分层采用“必做—选做—挑战”而非贴标签。高一和高二可混班实施：高二学生的优势体现在更复杂的验证、表达和协作职责，而不是简单地获得更多题量。

| 层级 | 任务特征 | 教师支持 |
|---|---|---|
| 必做 | 提供代码骨架与明确样例，保证可运行。 | 逐步提示、术语卡、同伴结对。 |
| 选做 | 改变阈值、增加字段、比较两种实现。 | 提供提示而非完整答案。 |
| 挑战 | 处理异常、封装函数、提出更可靠的数据解释。 | 以提问和代码审阅支持。 |

### 6.3 数据伦理与安全

课程禁止收集同学姓名、联系方式、精确位置、成绩、健康、家庭经济状况等敏感个人数据。课堂使用公开数据、教师提供的脱敏数据或明确标注为“教学模拟”的合成数据。任何项目都需要写明数据来源、字段含义、可能偏差与不应作出的推断；当学生以问卷采集数据时，必须采用自愿、匿名、最小必要原则，并经任课教师同意。

## 七、评价方案

评价以形成性证据为主，既关注程序是否正确，也关注是否理解数据、能否解释证据与承担责任。期末成绩可按下表汇总；学校如不需要量化总评，可保留量规描述作为发展性评价。

| 评价构成 | 比例 | 证据 | 核心标准 |
|---|---:|---|---|
| 课堂参与与调试档案 | 20% | 退出卡、调试记录、同伴测试。 | 愿意尝试、能描述错误并修复基本问题。 |
| 单元任务 | 35% | U1—U5 程序、知识图与反思。 | 程序可运行，概念能解释，数据处理有证据。 |
| 期末数据微项目 | 35% | 小组代码、数据故事页、展示与数据说明。 | 问题清晰、处理可复现、结论有边界、表达可信。 |
| 个人反思与数据责任 | 10% | 个人复盘、隐私与偏差声明。 | 识别限制，提出改进，遵守数据责任。 |

期末项目采用四维量规：技术实现 30%、数据处理与证据 30%、解释与表达 25%、责任与协作 15%。其中“数据处理与证据”不得以视觉效果替代；“责任与协作”要求每位成员说明自己负责的代码、数据或表达工作。

## 八、U1 与后续单元的衔接

首个资源包首先落地 U1《数据侦探的第一步》，以低门槛、小步反馈和可完成的“周数据小报”为学生建立成功体验。U1 所使用的 IPO 图、调试日志、反思卡和单元资源目录将成为后续五个单元的模板。U2—U5 在同一格式中增加新的 Python 与数据技能；U6 不新增核心语法，而是整合此前能力完成数据微项目。
