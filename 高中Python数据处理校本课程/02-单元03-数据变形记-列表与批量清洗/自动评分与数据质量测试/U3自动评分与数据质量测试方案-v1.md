# U3 自动评分与数据质量测试方案 v1.0

## 一、设计目标

本工具服务于 U3《数据变形记：列表与批量清洗》的课堂练习和结项项目自检。它不把学生作品压缩成一个不可解释的分数，而是检查学生提交的程序是否满足关键函数接口、清洗规则、批量分流、质量日志、汇总口径和原始数据保护要求，并给出下一步可操作的反馈。

工具只检查 Python 程序的可运行行为和有限的代码结构。规则表、流程图和 150—250 字质量说明仍需教师或同伴依据量规审阅。自动评分器不是安全沙箱，只能在普通课堂的隔离环境中运行可信的学生代码；不要运行来源不明的程序。

## 二、学生提交接口

学生提交文件命名为 `u3_submission.py`，必须提供以下两个函数：

```python
def clean_minutes(raw_value):
    """返回 (clean_value, issue_reason)。"""
    ...


def transform_records(raw_records):
    """返回 (clean_records, issues)。"""
    ...
```

`clean_minutes` 的返回值应为二元组。有效值为非负整数并且原因为空；问题值可返回 `None` 并提供非空原因。`transform_records` 应返回两个列表，第一项为有效记录列表，第二项为问题日志列表。

## 三、评分维度

| 维度 | 权重 | 自动检查 | 典型反馈 |
|---|---:|---|---|
| 单值清洗函数 | 20% | 空格、单位、空值、无效文本、负数、零值样例。 | “先标准化文本，再判断；不要把空值默认为 0。” |
| 批量处理 | 25% | 处理多条字典记录；有效/问题列表长度和去向。 | “检查循环和两个 `append` 分支。” |
| 质量日志 | 20% | 问题记录保留 `record_id`、`raw_value`、`reason`。 | “问题记录不能消失；请保留原始值与原因。” |
| 汇总口径 | 20% | 有效数、问题数、总分钟数、平均分钟数与清洗结果一致。 | “汇总必须说明分母和未纳入记录。” |
| 可追溯与结构 | 15% | 原始输入不被修改；函数可导入；无明显危险导入/调用。 | “请使用新列表保存清洗结果，不要覆盖原始列表。” |

评分器输出“通过/未通过”和分维度诊断，满分仅用于教师快速定位资源问题，不替代对流程图、测试记录和反思的评价。

## 四、测试数据与预期

### 1. 单值清洗测试

| 输入 | 期望值 | 期望问题 |
|---|---:|---|
| `"25"` | 25 | 空或 `None`。 |
| `" 35 "` | 35 | 空或 `None`。 |
| `"30分钟"` | 30 | 空或 `None`，本项目允许去除约定单位。 |
| `""` | `None` | 非空缺失原因。 |
| `"abc"` | `None` | 非空无效原因。 |
| `"-5"` | `None` | 非空负数原因。 |
| `"0"` | 0 | 空或 `None`。 |

### 2. 批量质量测试

```python
raw_records = [
    {"record_id": "R01", "day": "周一", "minutes": "25"},
    {"record_id": "R02", "day": "周二", "minutes": " 35 "},
    {"record_id": "R03", "day": "周三", "minutes": ""},
    {"record_id": "R04", "day": "周四", "minutes": "30分钟"},
    {"record_id": "R05", "day": "周二", "minutes": "35"},
    {"record_id": "R06", "day": "周五", "minutes": "abc"},
    {"record_id": "R07", "day": "周六", "minutes": "0"},
]
```

允许的有效记录数为 4 或 5：如果按约定清洗 `30分钟`，则为 5；如果把单位混入标为待复核，则为 4。评分器不强迫唯一规则，但要求程序输出与自身规则一致、保留问题证据并在结项说明中解释。

## 五、运行方式

```bash
python grade_u3.py u3_submission.py
```

如需输出 JSON 结果供教师汇总：

```bash
python grade_u3.py u3_submission.py --json-result u3_result.json
```

程序应显示总分、通过测试数、各维度结果和下一步建议。它不输出学生姓名、排名或公开成绩单。

## 六、评分边界

自动评分器不判断流程图是否美观、不判断反思文字是否“像标准答案”，也不根据代码长度评判能力。教师仍需使用 U3 结项任务书审阅清洗规则表、6 组测试、两次规则实验、流程图、质量说明和同伴试运行反馈。

## 七、安全边界

学生代码在子进程中运行并设置超时；评分器对常见导入、文件操作、系统调用和动态执行做静态拦截。但 Python 代码执行不能仅靠这种轻量检查获得完整安全保证。因此必须只运行可信课堂代码，在隔离目录中操作，不把评分器当作通用恶意代码沙箱。
