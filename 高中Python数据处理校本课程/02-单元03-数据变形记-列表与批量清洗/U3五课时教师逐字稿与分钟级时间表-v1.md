# U3《数据变形记：列表与批量清洗》五课时教师逐字稿与分钟级时间表 v1.0

**适用情境：** 高一、高二；已完成 U1 与 U2 的基础变量、条件、循环和函数学习；5 × 45 分钟；普通离线 Windows 机房。  
**单元产出：** 一个数据整理器程序、一张数据“变形”流程图、一份数据质量与清洗边界反思。  
**核心立场：** 清洗不是让数据“更好看”，而是用明确、可复现、可说明的规则处理问题，并保留无法自动确认的记录。

> **固定课堂句式：** “先看原始记录，再写处理规则；先保留原因，再做汇总；先解释去向，再报告数字。”

## 一、五课时总览

| 课次 | 核心问题 | 本课最小达成 | 当堂留下的证据 |
|---:|---|---|---|
| 1 | 怎样组织多条、不同字段的记录？ | 能区分列表与字典，并找出原始数据中的问题。 | 数据卡与问题分类表。 |
| 2 | 面对格式混乱的数据，凭什么这样处理？ | 能为 4 类问题写出清洗规则与理由。 | 清洗规则表与单值预测。 |
| 3 | 怎样把规则应用到每一条记录？ | 能让循环把记录送往有效列表或质量日志。 | 记录去向表与批量输出。 |
| 4 | 汇总时怎样不把问题藏起来？ | 能同时报告有效数、问题数和统计结果。 | 汇总输出与质量说明。 |
| 5 | 怎样让他人复核数据处理过程？ | 能提交程序、流程图、质量反思并完成同伴审阅。 | 三类成果与同伴反馈。 |

## 二、课前统一准备

教师准备 U3 学生学习单、`数据整理器_起始代码.py`、参考实现、数据卡、清洗规则表和流程图模板。课堂只使用既有教学模拟阅读记录；`record_id` 仅用于解释记录追溯与疑似重复，不能对应真实学生。教师不得要求学生收集同学的阅读、行为、成绩、位置或健康记录。

首次打开文件时，教师说明：原始数据与清洗后数据都要保留。学生不要直接覆盖 `raw_records`，也不要把空值擅自补为 0。出现环境问题时，先让学生在纸面上完成“原始值—规则—去向”表，再共享可用设备运行。

# 第 1 课：一条记录，还是一组数据？

**本课目标：** 区分一条字典记录与多条记录组成的列表；读懂键和值；从原始教学模拟数据中找出空格、缺失、单位混入、无效文本和可能重复。  
**教师材料：** 数值列表、单条字典卡、多条记录卡、原始 `raw_records`。  
**板书固定区：** `一条记录 = 字典；多条记录 = 列表`；`问题 ≠ 一定错误`。

| 时间 | 教学环节 | 教师逐字稿与操作 | 学生动作与教师观察 |
|---|---|---|---|
| 0:00—4:00 | 与 U1、U2 连接 | **教师说：**“U1 里我们处理的是一串数字；U2 里我们让函数按规则处理一组情境。今天数据更像真实生活：每一条记录有多个字段，而且它们不总是整齐。我们的任务不是删掉不喜欢的数据，而是让每条记录的去向可说明。” | 学生回忆列表、函数与规则。教师说明本单元不收集真实同学数据。 |
| 4:00—10:00 | 对比两种结构 | 展示 `weekly_minutes = [25, 35, 40]` 和 `{"record_id": "R01", "day": "周一", "minutes": "25"}`。**教师说：**“前者是一串同类值；后者是一条记录，里面有多个字段。请回答：如果我问的是‘周一的分钟数’，我该在什么位置找？” | 学生口头指出 `record["minutes"]`。教师检查是否把键和值反过来。 |
| 10:00—20:00 | 数据卡拼装 | **教师说：**“每组拿到字段卡和记录卡。先拼出一条字典记录，再把三条记录放进一个列表。拼完后，请用一句话解释：外层列表解决什么问题，内层字典解决什么问题。” | 小组拼装。教师巡视时追问：“这里是第几条？这里是这一条的哪个字段？” |
| 20:00—33:00 | 原始数据侦错 | 投影 `raw_records`，不给任何处理规则。**教师说：**“现在先当数据侦探。请找出你认为需要注意的值，但不要急着叫它‘错误’。空白一定代表 0 吗？周二两条 35 一定是重复吗？” | 学生圈出 `" 35 "`、`""`、`"30分钟"`、`"abc"`、疑似重复。教师要求至少找出 3 类现象。 |
| 33:00—40:00 | 问题分类 | **教师说：**“请把你发现的现象分成三类：可按规则修复；需要标记；需要人工复核。重点是写出理由。” | 完成分类表。若学生说“abc 直接删”，追问：“删掉后，别人怎样知道原来有一条无法解释的记录？” |
| 40:00—43:00 | 公共复盘 | **教师说：**“空白和 0 的区别是什么？疑似重复和确定重复的区别是什么？今天我们先不处理，先学会保留不确定性。” | 2—3 名学生回答。教师将“未知不等于没有”写在板书。 |
| 43:00—45:00 | 退出卡与收束 | **教师说：**“写下一个键和值的例子，再写下一个你认为必须标记而不能自动删除的现象。下节课，我们先立规则，再动数据。” | 提交退出卡，保存数据卡。 |

**即时调整规则：** 若多数学生把列表和字典混用，用颜色把外层列表和内层字典圈出，并要求说出“多条/多个字段”。若多数学生主张直接删除问题记录，下节课开场先对比“有日志”和“无日志”两种汇总的可解释性。

# 第 2 课：先立规则，再动数据

**本课目标：** 为空格、单位混入、缺失、无效文本等问题建立明确规则；理解 `str()`、`strip()`、`replace()`、`isdigit()`、`int()` 的转换链；能预测单值清洗函数的返回结果。  
**教师材料：** 清洗规则表、单值卡、`clean_minutes()` 骨架。  
**板书固定区：** `原始值 → 标准化 → 判断 → 数字或原因`；`规则先于删除`。

| 时间 | 教学环节 | 教师逐字稿与操作 | 学生动作与教师观察 |
|---|---|---|---|
| 0:00—3:00 | 回顾问题 | **教师说：**“昨天我们发现了问题，今天决定怎样处理。最重要的原则是：不能因为程序能做某件事，就默认它应该做。每一步都要有规则和理由。” | 学生回顾 4 类问题。 |
| 3:00—11:00 | 建立清洗规则表 | 投影 4 类现象。**教师说：**“请为每一类填四格：原始格式、预期格式、处理方法、是否进入汇总。特别注意：空白和 `abc` 不进入汇总，但它们不能消失。” | 学生填写规则表。教师检查是否记录“保留原始值和原因”。 |
| 11:00—20:00 | 拆解转换链 | 演示：`" 35 "` → `str()` → `strip()` → `"35"` → `isdigit()` → `int()` → `35`。**教师说：**“每个方法只做一件小事。它们不是魔法，必须说明这一步把什么变成什么。” | 学生用箭头标注转换。若问 `isdigit()` 是否万能，说明它只服务本单元的“非负整数分钟数”约定。 |
| 20:00—30:00 | 单值预测 | 发放 `""`、`"30分钟"`、`"abc"`、`" 35 "`、`"0"`。**教师说：**“先在纸面写出函数应返回‘数字/None’和原因，再运行。预测错误不可怕，关键是能看见规则在何处不同。” | 学生填写预期与实际。教师关注是否把空白当作 0。 |
| 30:00—39:00 | 补全函数 | 展示 `clean_minutes(raw_value)` 骨架。**教师说：**“函数要交回两个结果：清洗后的分钟数，或一条问题原因。这样后面的循环才知道该把记录放到哪里。” | 学生补全或改写函数。教师巡视提问：“当 `text == ""` 时，为什么返回 None 而不是 0？” |
| 39:00—43:00 | 小组核对 | **教师说：**“两人交换一条规则表，只问三个问题：这条规则处理什么？为什么这样处理？原始记录和原因是否仍能追溯？” | 同伴提出一项修订建议。 |
| 43:00—45:00 | 收束 | **教师说：**“下节课，同一个函数会被循环用于每一条记录。记住：批量处理不等于批量删除。” | 保存函数和规则表。 |

**即时调整规则：** 若学生只记方法名却说不出转换目的，暂停补全函数，改用三条值的纸面箭头流程。若把空值普遍处理为 0，增加“未知、零、无效”三栏对照活动。

# 第 3 课：让循环批量变形

**本课目标：** 追踪一条记录进入有效列表或质量日志的过程；使用循环调用单值清洗函数；理解 `append()` 将结果放入不同清单；能解释修改一条原始数据后记录数如何变化。  
**教师材料：** `transform_records()` 骨架、记录去向表、原始数据。  
**板书固定区：** `原始记录 → clean_minutes() → 有效列表 / 问题列表`；`原始列表仍保留`。

| 时间 | 教学环节 | 教师逐字稿与操作 | 学生动作与教师观察 |
|---|---|---|---|
| 0:00—4:00 | 函数与循环连接 | **教师说：**“昨天函数处理一个值。今天循环把每一条记录依次送进同一函数。函数负责判断一个值；循环负责重复这个过程；两个结果清单负责保留不同去向。” | 学生说出三者分工。 |
| 4:00—12:00 | 单条记录追踪 | 选 R04 `"30分钟"`，逐步走过清洗；再选 R06 `"abc"`。**教师说：**“请填写：原始值是什么，规则如何判断，最后去哪一个列表，为什么？” | 学生完成去向表。教师强调 R06 不进入汇总，但保留 `record_id`、原始值和原因。 |
| 12:00—23:00 | 循环骨架 | 展示 `for record in raw_records:`。**教师说：**“每一轮的 `record` 是当前这一条字典。拿到 `record["minutes"]` 后，函数给我们‘数字和问题原因’。根据原因是否为空，再 `append` 到不同列表。” | 学生补全循环和两个 `append`。教师巡视问：“这一次循环处理的是第几条？为什么它进入这个清单？” |
| 23:00—33:00 | 批量运行 | **教师说：**“运行后不要只看成功信息。请同时看原始记录数、有效记录数、问题记录数。三者之间关系是否能解释？” | 学生运行并记录数量。教师提示：总数应等于有效数加问题数，除非有明确的第三类状态。 |
| 33:00—41:00 | 修改一条数据 | **教师说：**“现在只改 R06 的 `"abc"` 为 `"45"`。先预测：有效记录数、问题记录数、总量和均值哪些会变？再运行。” | 学生预测、运行、解释。教师观察是否能从“记录去向改变”解释汇总变化。 |
| 41:00—44:00 | 退出卡 | **教师说：**“写一句：循环重复的是什么？`append` 做的是什么？原始记录为什么仍然要保留？” | 独立作答。 |
| 44:00—45:00 | 收束 | **教师说：**“下节课我们汇总，但不会让问题记录消失。数字必须带着处理过程一起出现。” | 保存程序。 |

**即时调整规则：** 若输出数量不匹配，先检查循环缩进和 `append` 的分支位置。若学生把原始列表覆盖掉，恢复原始变量并要求另建 `clean_records`，不要继续加入新功能。

# 第 4 课：汇总不是忽略问题

**本课目标：** 基于有效记录计算总量、平均值、最大/最小值与有效记录数；输出问题记录数量和原因；说明汇总结论依赖哪些记录与规则。  
**教师材料：** 清洗后列表、`issues`、汇总骨架、两种清洗结果对比卡。  
**板书固定区：** `统计结果 + 有效记录数 + 问题记录数 + 处理规则`。

| 时间 | 教学环节 | 教师逐字稿与操作 | 学生动作与教师观察 |
|---|---|---|---|
| 0:00—3:00 | 发现不完整结论 | 投影：“平均阅读 31 分钟。”**教师说：**“这句话可能没有错，但它还缺什么？基于几条记录？哪些记录没进入计算？为什么？” | 学生指出有效数和问题数。教师板书“汇总要带脚注”。 |
| 3:00—9:00 | 确定汇总前提 | **教师说：**“我们只对 `clean_records` 做统计，不用 `raw_records`。这不是因为原始数据没价值，而是因为我们要先说明哪些数据满足了本单元的格式规则。” | 学生指出两个列表分别承担什么角色。 |
| 9:00—21:00 | 完成统计 | 提供总量、最大最小、平均值骨架。**教师说：**“先手算前两条有效记录，再让循环累计。每个统计量都要能回答：它的分母是多少？它排除了什么？” | 学生补全统计、运行并对照至少一项手算。 |
| 21:00—31:00 | 质量日志 | **教师说：**“问题记录不是垃圾桶。请输出问题记录数，并读出至少两条 `record_id + reason`。别人看到汇总时，必须知道哪些记录没有被算进去。” | 学生查看 `issues`，输出问题数和原因。 |
| 31:00—39:00 | 规则比较 | 提供情境：将 `"30分钟"` 视为可修复，或视为待复核，会对有效数和均值产生什么影响？**教师说：**“不要因为一个数字更好看就选规则。请用字段口径、可解释性和可复现性说明理由。” | 小组比较两种规则，写理由。 |
| 39:00—43:00 | 完整结论 | **教师说：**“请用句式完成：‘在 ______ 条有效记录中，平均为 ______；另有 ______ 条记录未进入计算，原因包括 ______。’” | 独立写作。教师检查是否避免过度推断。 |
| 43:00—45:00 | 收束 | **教师说：**“下节课，我们不只展示数字，还要让别人沿着流程图复核每一条数据的去向。” | 保存汇总输出。 |

**即时调整规则：** 若学生只报平均值，不报有效数和问题数，禁止进入展示准备，先补齐质量日志输出。若学生认为“删除更多问题记录更好”，回到规则比较卡，要求说明删除后的可追溯性损失。

# 第 5 课：发布数据变形记

**本课目标：** 完成数据整理器自测、数据去向流程图、同伴代码审阅和质量反思；在展示中说明自动修复、标记记录和人工复核边界。  
**教师材料：** 单元量规、流程图模板、同伴审阅表、模拟修改数据。  
**板书固定区：** `原始数据 → 规则 → 有效/问题 → 汇总`；`可追溯比“看起来整齐”更重要`。

| 时间 | 教学环节 | 教师逐字稿与操作 | 学生动作与教师观察 |
|---|---|---|---|
| 0:00—3:00 | 明确交付 | **教师说：**“今天提交三项：可运行的数据整理器、能说明数据去向的流程图、能说明清洗边界的反思。展示不是报告一个平均数，而是让别人知道这个平均数从哪里来。” | 学生打开量规与提交清单。 |
| 3:00—13:00 | 自测完善 | **教师说：**“至少做两次修改：把一个无效值改为可修复值；把一个可修复值改为缺失。每次先预测有效数、问题数和汇总会怎样变化，再运行。” | 学生自测。教师优先支持未能稳定输出三类清单的学生。 |
| 13:00—21:00 | 画流程图 | 教师示范五步：原始记录、规则判断、清洗/标记、有效数据与质量日志、汇总。**教师说：**“至少让空格、单位混入、缺失、无效文本四类问题在图中有不同去向。” | 学生绘图。教师检查流程图是否保留问题日志。 |
| 21:00—29:00 | 同伴代码审阅 | **教师说：**“交换程序。同伴只检查四点：原始数据是否保留；每类问题是否有规则；问题记录是否有原因；汇总是否报告有效数和问题数。请留下一条具体、可执行的改进。” | 同伴运行与审阅。 |
| 29:00—39:00 | 数据侦探局报告 | **教师说：**“每组 90 秒，必须说四句：我自动修复了……；我标记了……；汇总基于……条有效记录；这份数据不能说明……。观众提问只围绕规则理由、数据去向和人工复核。” | 选 4—6 组展示。教师记录高质量反思和典型遗漏。 |
| 39:00—43:00 | 质量反思 | **教师说：**“完成 150—250 字说明：哪一条记录不能自动修复；哪一条规则有风险；如果进入真实 CSV 数据，下一步还需要什么信息或人工复核。” | 独立写作。 |
| 43:00—45:00 | 提交与收束 | **教师说：**“请提交程序、流程图和质量说明。U3 最重要的收获是：数据处理不是把问题藏起来，而是把规则和问题一起留下证据。” | 提交三类成果。 |

## 三、试教后的复盘提示

U3 首轮试教后只确定一项 P0 修订。例如，若学生普遍将空值改为 0，就在第 2 课增加“未知、零、无效”的对照卡；若学生普遍只报告均值，就在第 4 课将“有效数和问题数”设为不可省略的输出。不要在同一轮同时改写数据、清洗函数、流程图和评价量规。
